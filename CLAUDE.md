# RidgeRacerType4Recomp Rules

Static recompilation of **R4: Ridge Racer Type 4 (USA)** — serial
**SLUS-00797**, boot EXE `SLUS_007.97` — to native code, built with the shared
**psxrecomp** framework. The goal is a binary that plays without an emulator
behind it, like TombaRecomp and MegaManX6Recomp.

## Inheritance

This project inherits, in order:

1. The framework constitution at `psxrecomp/CLAUDE.md`. Read it first: no MIPS
   interpreter as the answer, no HLE BIOS shims, no stubs, recompiled BIOS
   first, fix the framework/runtime/config and **regenerate** — never hand-edit
   `generated/`.
2. The repo shape of `mstan/MegaManX6Recomp`, updated to the framework's
   New Project Layout (`psxrecomp/` + `recomp-ui/` root submodules,
   `psxrecomp_add_game_runtime`, `codegen_setup.c`).

## Project rules

- Game binaries (disc image, extracted boot EXE, Ghidra dumps), Ghidra
  databases, memory cards, overlay captures, and build outputs are **local
  only** and must not be committed. See `.gitignore`.
- Tracked: `game.toml`, `seeds/`, `annotations/`, `symbols.toml`,
  `ghidra/instructions.txt`, `ghidra/scripts/`, `CMakeLists.txt`,
  `codegen_setup.*`, `src/mods/`, `tests/`, `tools/`, `scripts/`,
  `mods/preloaded/`, docs, and `generated/` (the recompiled game C).
- `generated/` is committed because releases are compiled from it
  (bundled releases, psxrecomp `docs/ci/BUNDLED_RELEASES.md`). Regenerate it
  with `tools/regen.sh` after any seed, annotation, `[recompiler]` or pin
  change and commit the result in the same change. The BIOS backends live in
  the `psxrecomp` submodule, never here.
- Codegen/runtime fixes belong in the framework (`psxrecomp/`) or in per-game
  `game.toml` config — never by hand in `generated/*.c`. A fix only this game
  needs is a smell; prefer a class fix the next title inherits.
- After every run, resolve all dispatch misses before any other debugging.
- The framework and launcher versions are the `psxrecomp` and `recomp-ui`
  submodule gitlinks. Bump them deliberately; record why in
  `docs/framework_pin_history.md`.
- Base 4:3 uses the stock psxrecomp renderer. Widescreen is the
  `r4.enhancement.widescreen` mod on psxrecomp's native-wide renderer
  (`docs/WIDESCREEN.md`), on by default for R4 (owner, 2026-10-01; README
  "On by default"); its `[widescreen.cull]` lists in
  `game.toml` are generated by `tools/r4_ws_scan.py` and checked with
  `tools/r4_ws_scan.py --check game.toml`.
- Disc identity and hashes live in `DISC.md`; verify a dump against them before
  blaming a regression.

## Workflow (owner rules)

- Develop on `master` in `~/dev/ridgeracertype4` on the Mac. Pull before
  editing, coordinate dirty work, and commit small, coherent changes.
- Use short-lived topic branches and PRs only when review needs isolation.
  No worktree pairs or integration branches. Delete landed topic branches.
- Until the three R4 engine fixes merge upstream, pin `tetrisgm/psxrecomp`
  on its single development branch `master`, with one upstream PR per fix.
  Then pin verified upstream master, change `.gitmodules` to
  `RetroPortingToolKit/psxrecomp`, and archive the fork. Track PRs in
  `docs/UPSTREAM.md` and pin changes in `docs/framework_pin_history.md`.
- Use upstream `recomp-ui`; the old custom `recomp-launcher` is retired.
- Engine enhancements remain elective and opt-in. Preserve the faithful
  base path; game-owned enhancements belong in this repository.
- Build and test only on the Mac. Before every push, pass a Release build,
  CTest and `tools/smoke.py` against an isolated hidden runtime with dummy
  audio. Preserve native saves and explicit player settings.
- Cross-build Windows on the Mac using `docs/WINDOWS_BUILD.md`. Deliver
  portable, checksummed builds to a fresh `builds/r4/<version>/` folder on
  the NAS. Never reuse a version folder, bundle game data, or publish a
  release/feed. If the share is unavailable, retain the build locally.
- STEAMBOX is a gaming console: never connect to or operate it, and never
  install development tools there. The owner tests finished builds by hand.
- Never force-push. Backup, archive and recovery branch deletion requires
  the owner's explicit approval of the exact deletion list.

## Screen rules (owner, 2026-10-27)

- Automated Mac runs use `--hidden-window`, dummy audio and debug-server
  dumps. Windows playtest results come only from the owner.
- PGXP (geometry correction + perspective texturing) is never turned off or
  made a fallback, and is never run off even as a test reference (owner,
  2026-10-27). Bisect among its sub-features; fix or disable the faulty one.
- Kill only processes you started; if the owner closes the game, it stays
  closed.
